#Тестирование #Android

Для реализации этой схемы используется механизм **ADB reverse port forwarding**, который перенаправляет трафик с локального порта смартфона на порт Charles на ПК.  

***Шаг 1. Подготовка Charles Proxy на ПК***
Запустите Charles.  
Перейдите в **Proxy** -> **Proxy Settings**.  
Убедитесь, что в поле **HTTP Proxy Port** указан дефолтный порт 8888 (или любой другой свободный порт).  
Нажмите **OK**.  

**Шаг 2. Подготовка Android-смартфона**  
**Включите режим разработчика:** Откройте _Настройки -> О телефоне_ и нажмите на _Номер сборки_ 7 раз.  
**Включите отладку по USB:** Перейдите в _Настройки -> Для разработчиков_ и активируйте тумблер **Отладка по USB (USB Debugging)**.  
Подключите смартфон к ПК по кабелю. При появлении запроса на экране телефона разрешите отладку с этого компьютера.  

**Шаг 3. Проброс портов и активация прокси через ADB**  
Для этого шага на вашем ПК должен быть установлен **ADB** (Android Debug Bridge) из состава Android SDK Platform Tools.  
Откройте терминал (macOS/Linux) или командную строку/PowerShell (Windows).  
Проверьте, что устройство видно системе:`adb devices` _(В списке должен появиться серийный номер вашего устройства)_  

**Свяжите порты по кабелю:** Направьте трафик с порта 7777 смартфона на порт 8888 компьютера (где запущен Charles):

`adb reverse tcp:7777 tcp:8888`  

**Включите системный прокси на Android:** Укажите устройству слать весь трафик на его собственный локальный порт, который мы только что пробросили:

`adb shell settings put global http_proxy localhost:7777`  


> 💡 **Как всё вернуть назад (когда закончите работу):** Чтобы отключить прокси и вернуть интернет в нормальное состояние, выполните две команды:  
> 
> adb shell settings put global http_proxy :0 adb reverse --remove-all  

**Шаг 4. Установка SSL-сертификата (для HTTPS-трафика)**  
Без этого шага вы будете видеть вместо данных внутри HTTPS-запросов лишь зашифрованный шум (<unknown>).  

В Charles перейдите в **Help** -> **SSL Proxying** -> **Save Charles Root Certificate...** и сохраните файл сертификата (например, charles.crt).  
Закиньте этот файл в память телефона (через тот же кабель).  
На телефоне перейдите в _Настройки -> Безопасность (или Конфиденциальность) -> Дополнительные настройки -> Шифрование и учетные данные -> Установка из памяти устройства_.  
Выберите **Сертификат CA** (CA Certificate), проигнорируйте предупреждение системы безопасности и выберите файл charles.crt.  
В самом Charles зайдите в **Proxy** -> **SSL Proxying Settings**, поставьте галочку **Enable SSL Proxying**, нажмите **Add** и введите в поля _Host_ и _Port_ звездочки * (чтобы перехватывать всё), либо укажите конкретные домены вашего API.  

**⚠️ Важный нюанс для современных Android (Android 7.0 и выше)**  
Начиная с Android 7, приложения по умолчанию **игнорируют пользовательские SSL-сертификаты** ради безопасности. Если вы дебажите чужое приложение из Google Play, вы всё равно можете увидеть SSL Handshake Failed.  

Чтобы перехватывать трафик конкретного приложения, у вас есть три пути:  
**Если приложение ваше (есть исходный код):** Добавьте файл network_security_config.xml в ресурсы проекта и пропишите туда доверие к <certificates src="user" />.  

**Если приложение чужое (нужен root-доступ):** С помощью Magisk-модулей (например, _AlwaysTrustUserCerts_) можно переместить сертификат Charles из пользовательского хранилища в системное.  

**Без root (для чужих приложений):** Использовать инструменты автоматической пересборки APK (например, **apk-mitm**) для внедрения разрешения на проксирование прямо в код приложения, либо использовать встроенные скрипты отладки в эмуляторах.
